[제품 소개](../README.md) · [판정 규칙](IMPLEMENTATION.md)

## 실행 방법

Python 3.10 이상에서 저장소 최상위 폴더를 기준으로 실행합니다. 표준 라이브러리만 사용하며, API 키·운영 DB·외부 네트워크 연결은 필요하지 않습니다.

```bash
python3 -I -B examples/demo.py
python3 -I -B tests/test_price_gate.py -v
```

첫 명령은 [합성 입력](../examples/scenarios.json)의 판정 결과를 출력합니다. 둘째 명령은 [기대 결과](../examples/expected.json)와의 비교 및 개별 경계 검사를 실행합니다.

## 시나리오별 기대 결과

A의 상품가는 12,000원, 배송비는 3,000원으로 총 15,000원입니다. 아래는 같은 상품·용량·수량이라는 전제에서 B와 비교하거나, 충돌·오류 행을 추가한 경우입니다.

| 입력 상황 | 통과 후보 | 확인할 동작 |
|---|---|---|
| A 총액 15,000원, B 총액 16,000원 모두 확인 | A·B | 이 단계는 1위가 아니라 가격 검사 통과 후보를 반환합니다. |
| B의 배송비 미확인, 상품가 16,000원 | A | B는 배송비를 더하기 전에도 A보다 비쌉니다. |
| B의 배송비 미확인, 상품가 15,000원 | 없음 | 현재 규칙은 미확인 후보와의 동률 가능성도 보류합니다. |
| B의 배송비 미확인, 상품가 14,000원 | 없음 | B가 더 저렴할 가능성이 남습니다. |
| 원본 규칙과 일치하는 조건부 배송 행 | A | 조건부 행을 남기되 일반 가격 경쟁에서 분리합니다. |
| 같은 조건부 행에서 `Y` 대신 `y` | 없음 | 정확한 필드 조합만 예외로 처리합니다. |
| 같은 판매처·옵션으로 묶인 행들의 가격 충돌 | 없음 | 충돌이 있으면 표의 후보 선정을 보류합니다. |
| 상품가+배송비와 보고 합계 불일치 | 없음 | 해당 행의 합계를 확정하지 못해 표의 후보 선정을 보류합니다. |

[테스트 코드](../tests/test_price_gate.py)는 이 외에도 음수 배송비, 상품가 0, 근거와 전달 금액의 불일치, 판매처명 누락, 다른 출처, 목적지 불일치, 깨진 근거 금액, 충돌 표시를 검사합니다. 빈 표·중복 행, 입력 객체를 변경하지 않는지, 조건부 배송 행이 다른 미확인 경쟁 행을 가리지 않는지도 확인합니다.

## 무엇을 확인하는 테스트인가?

이 테스트는 **합성 입력에서 가격 검증 코드가 정한 규칙대로 동작하는지** 확인합니다. 가격과 근거 객체는 같은 파싱 결과에서 연결되며, 실제 판매처의 현재 결제가와 교차검증하지 않습니다.

상품 식별 정확도, 전체 수집·게시·앱 동작, 실제 가격 오류 감소율과 사용자 효과는 이 테스트로 측정하지 않습니다. 동률 보류와 예제의 범위는 [구현 설명](IMPLEMENTATION.md#ties)에서 확인할 수 있습니다.

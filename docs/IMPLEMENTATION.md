# 구현 경로와 경계

## 전체 제품에서 이 예제가 차지하는 위치

다음은 검토한 기존 코드의 연결 관계다. 전체 시스템을 이 공개본에서 실행할 수 있다는 뜻은 아니다. 파일명은 원본 프로젝트 내 모듈명이며, 공개되지 않은 원본으로의 링크는 제공하지 않는다.

| 단계 | 확인한 구현 | 역할 |
|---|---|---|
| 수집 | `cli.collect_live`, `danawa`, `community.collect_recent_config`, `retail` | 가격비교·개인 핫딜 기반 후보·편의점 행사 어댑터를 통해 후보 수집 |
| 보존·정리 | `cli.validate_discoveries`, `state.record_scan`, `core.build_offer` | 수집 후보와 거절 이유를 보존하고, 음료 여부·구성·용량·수량·가격을 정리 |
| 검증 | `price_evidence`, 상품 식별 판정, 검증 작업/결과 | 가격 증거, 정확한 상품·판매 옵션, 일반 공개 조건을 구분 |
| 가격 비교 | `app_read_model._candidate`, `build_app_read_model` | 유효 후보의 배송비 포함 최종가/수령 용량으로 원/L 계산, 상품·모드·용량별 순위 생성 |
| 앱 제공 | `static_data`, `miniapp/src/api.ts` | 앱용 결과를 정적 JSON으로 내보내고 클라이언트가 필요한 가격판·상세만 읽음 |

`core.build_offer`는 전달받은 최종가로 원/L를 계산한다. 이 함수만 복사해서 배송비까지 검증한다고 설명하면 틀리다. 소스 어댑터의 합계 구성과 후속 게시 검증이 함께 필요하다. 편의점 어댑터는 지불 수량과 수령 수량을 구분해 전달한다.

이 앱의 가격 처리 전부를 LLM 파이프라인으로 표현하지 않았다. Hotdeal Agent의 자연어 피드백 구조화·재처리 코드는 별도 기능이며, 이번 공개 경로에는 LLM이 없다.

## 이번에 실행하는 한 경로

```text
합성 판매처 표
  → parse_price_compare_sellers: 계산 가능한 행과 불완전한 행을 함께 유지
  → _seller_table_settlement: 표 전체의 가격 충돌과 미확인 가격 하한 판정
  → demo.evaluate: 목적지와 행별 증거 연결 (공개용 어댑터)
  → price_comparison_row_is_publishable: 증거와 금액이 맞는지 공통 판정
  → gate_eligible 출력
```

원본에서는 `fetch_comparison_offers`가 목적지 해석과 행별 증거를 연결한다. 공개본은 그 네트워크 호출을 제거하고 예약 도메인 `shop.example.test`의 합성 URL을 공급한다. **실제 목적지 해석의 성공을 검증하지 않는다.** `state.record_scan`의 검증 큐 분기와 `app_read_model._complete_aggregator_evidence`는 같은 공통 가격 증거 함수를 호출한다.

### 판단 기준

- 완전한 행: 양수 상품가, 확인된 0원 이상의 배송비, 상품가+배송비와 보고 합계 일치. 원본은 보고 합계 `0`/누락을 미제공 값으로 취급하고 합계를 계산하는 동작도 유지한다.
- 완전한 표: 가격 충돌이 없고 행별 증거가 맞으면 여러 행이 통과할 수 있다. 이 함수가 1위 하나를 고르는 것은 아니다.
- 불완전한 표: 확인된 최저 합계보다 미확인 행의 상품가 하한이 모두 높아야 한다. 같은 가격도 통과 근거가 되지 않는다.
- 조건부 배송: `deliveryPrice=16777215`, `differentialPostYN='Y'`, 양수 상품가와 같은 `priceOrder` 등 원본의 정확한 조건이 맞아야 일반 공개가 경쟁에서 분리한다. 이것은 원본 어댑터의 소스별 표식이다. 무료 배송비나 보편적인 커머스 규칙으로 해석하면 안 된다.
- 조건부 행 자체는 불완전한 행으로 남는다. 다른 미확인 행이나 가격 충돌까지 무시하지 않는다.
- 공통 게이트: 출처 종류, 목적지 문자열, 판매처명 존재, 증거에 적힌 금액과 전달 금액, 합계 일치를 확인한다.

### 다루지 않는 것

게이트는 신뢰된 내부 증거 객체를 받는 함수다. 목적지의 HTTPS 접두부·문자열 일치를 검사하지만, URL 소유권·접속 성공·실제 판매 옵션을 인증하지 않는다. 임의 외부 JSON에 대한 완전한 스키마 검증기도 아니다. 원본의 `int()` 변환과 타입 가정을 바꾸지 않았다.

상품명·맛·용량·옵션 일치 판정, 회원/쿠폰 조건, 만료와 신선도, 이상 단가 격리, 원/L 순위, 데이터 저장·재시도·게시·앱 동작은 별도 경로다. 따라서 출력이 `true`여도 앱 공개 완료나 구매 가능 보장을 뜻하지 않는다. 합성 입력의 검증 사례는 회귀 확인이며 실제 LLM 성능·실사용 정확도 평가가 아니다.

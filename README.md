온라인 24캔 묶음과 편의점 2+1, 어느 쪽이 더 쌀까요? 표시 가격 대신 **실제로 내는 금액 ÷ 받는 음료의 총 용량**으로 비교합니다.

- **온라인 가격** — 배송비를 포함한 원/L와 구매 수량 확인
- **편의점 행사** — 증정 수량을 반영해 체인별 행사 비교
- **내 가격표** — 비교할 음료와 용량을 고르고, 상세에서 계산 근거 확인

## 맡은 일

처음부터 많은 상품을 고르게 하기보다, 첫 화면에 펩시와 코카콜라의 리터당 가격을 보여주고 다른 음료는 설정에서 검색해 추가하도록 정했습니다. 맛은 구분하고 용량 상한은 355·500·1,500·2,000mL로 선택 범위를 정했습니다.

기획·제품 판단·검토·운영을 맡았으며, 코드 구현은 AI 코딩 도구와 협업했습니다. 개인용 할인상품 수집 도구인 **Hotdeal Agent**의 수집 기반을 활용하고, 음료의 구매 조건 검증과 가격 비교 화면으로 확장했습니다.

<a id="flow"></a>
## 가격표가 만들어지는 흐름

```text
가격·행사 수집
    ↓
상품·맛·용량·수량과 구매 조건 정리
    ↓
상품·판매 옵션 및 가격 검증
    └─ 판매처 표의 가격 검사 ← 이 저장소에서 실행할 수 있는 부분
    ↓
리터당 가격 계산·순위
    ↓
가격판과 상세 화면
```

이 저장소는 제품 소개와 **기존 가격 검증 코드의 오프라인 실행 예제**를 담고 있습니다. 배송비를 모르는 판매처가 섞여 있을 때 비교를 계속할 수 있는지 보여주기 위해 이 부분을 분리했습니다.

<a id="price-check"></a>
## 배송비를 모르면, 최저가라고 할 수 있을까?

배송비를 모른다고 0원으로 계산하면 총액이 틀릴 수 있습니다. 반대로 그 판매처를 지워버리면 더 저렴할 가능성을 놓칩니다. 이 예제는 **가격 계산이 불가능한 행도 판정에 남겨 두고, 확인된 가격보다 더 쌀 가능성이 있는지** 검사합니다.

같은 상품·용량·수량을 판매하는 A와 B를 비교해 보겠습니다. A는 상품가 12,000원에 배송비 3,000원으로 총 15,000원입니다. B의 배송비는 모르지만 상품가는 알고 있습니다.

| B의 상품가 | 현재 규칙에서 A를 비교 후보로 쓸 수 있나? |
|---|---|
| 16,000원 | 예. 배송비를 더하기 전에도 A보다 비쌉니다. |
| 15,000원 | 보류. 미확인 후보가 동률일 가능성도 보류하는 규칙입니다. |
| 14,000원 | 보류. B가 더 쌀 수 있습니다. |

배송비가 0원 이상이고, 별도 할인이 상품가를 낮추지 않는다는 전제입니다. 비교 범위는 입력으로 받은 판매처 표와 일반 구매 조건입니다. 동률 보류는 공동 최저가를 허용하는 기준보다 보수적이며, [구현 설명](docs/IMPLEMENTATION.md#ties)에서 그 차이를 다룹니다.

같은 판매처·옵션으로 묶인 행들의 가격 충돌, 상품가·배송비와 보고 합계의 불일치도 검사합니다. 결과는 **이 가격 검사를 통과한 후보**이며, 상품 구성 확인과 최종 원/L 순위는 별도 단계입니다.

## 직접 실행

저장소를 내려받은 뒤 최상위 폴더에서 실행합니다. Python 3.10 이상이며 패키지 설치나 API 키는 필요 없습니다.

```bash
python3 -I -B examples/demo.py
python3 -I -B tests/test_price_gate.py -v
```

첫 명령은 합성 판매처 표의 판정 결과를 출력하고, 둘째 명령은 테스트를 실행합니다. `gate_eligible`이 통과 후보입니다. 예를 들어 `partial_lower`에서는 B의 상품가가 14,000원이어서 A보다 저렴할 가능성이 남으므로 빈 목록이 나옵니다.
